# 결제 서비스는 포트로 감싸고, 토스 키가 없으면 내장 모의 결제 서비스를 쓴다

후원은 토스페이먼츠 테스트 모드로 결제하지만, 토스 테스트 키는 개발자센터 가입 후에만 받을 수 있고 웹훅은 공개 주소에만 등록할 수 있어 로컬에서 성공·실패·취소·중복 통지를 재현하기 어렵다. 그래서 결제 서비스를 `confirm`·`getPayment` 두 가지만 가진 포트로 감싸고, 토스와 똑같은 흐름(결제창 → successUrl/failUrl 리다이렉트 → 서버 승인 → 상태 변경 웹훅)을 흉내 내는 **모의 결제 서비스**를 앱 안에 두었다. `.env` 에 토스 테스트 키가 있으면 토스를, 없으면 모의 결제를 쓴다. 승인 검증과 중복 방지는 결제 서비스와 상관없이 한 곳(`donation.service.js`)에서 한다.

## Consequences

- 모의 결제 서비스(`/mock-pay.html`, `/mock-pg/*`)는 실제 결제가 아니다. 운영 배포에서는 `PAYMENT_PROVIDER=toss` 로 고정해 모의 결제 경로가 열리지 않게 해야 한다.
- 다른 결제 서비스(Stripe 등)를 붙일 때는 같은 포트를 구현하는 어댑터만 추가하면 된다.
